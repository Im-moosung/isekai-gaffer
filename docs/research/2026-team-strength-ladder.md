# 팀 전력 사다리 재보정 — FIFA 랭킹과 난이도를 일치시킨다

> **조사일**: 2026-08-01
> **문제**: 상대 팀의 체감 난이도가 FIFA 랭킹 순서와 어긋났다. 7위 모로코가 60위 남아공과 같았고,
> 1위 아르헨티나가 강팀 중 가장 쉬웠다.
> **원칙**: 엔진에 팀별 보정 계수를 넣지 않는다. 스쿼드 데이터(선수 능력치·배열 순서·`statBaseline`)만 고친다.
> **측정 하네스**: `tools/team-balance/` — `run.mjs`(ladder·zones·calib), `xi.mjs`, `reorder.mjs`, `recalibrate.mjs`, `annotate.mjs`

---

## 1. 실측 방법

한국(랭킹 25) 기본 전술로 상대 11개국을 각 **4000시드** 90분 완주한다(총 44,000경기).
시드는 `7000 + i*31`의 정수뿐이다 — `Math.random`·`Date` 미사용.

n=4000에서 승률의 표준오차는 약 0.8%p다. **n=60은 SE가 6.5%p**라 10%p 미만의 차이는
읽을 수 없다 — 초기 조사가 n=60이었던 탓에 중위권 다섯 팀이 "한 덩어리"로 보였다.

측정은 **격리 git worktree**에서 했다. 저장소에 다른 갈래의 미커밋 변경이 있으면
밸런스 수치가 오염된다(이 저장소에 전례가 있다).

## 2. 진짜 원인은 능력치가 아니라 **배열 순서**였다

`engine/fitness.positionFitness`는 **자질을 보지 않는다**.

```
if (player.position === slot) return 1.0
if (player.altPositions.includes(slot)) return 0.85
```

그래서 `engine/lineup.pickBestXI`의 정렬은 같은 포지션끼리 전부 1.0 동점이 되고,
`Array#sort`가 안정 정렬이라 **squad 배열에 먼저 적힌 선수가 선발**이 된다.

12개 팀 JSON이 전부 **등번호순**으로 적혀 있었다. 즉 모든 팀이 "등번호가 빠른 XI"로 뛰고 있었다.

| 팀 | 등번호순 XI가 벤치에 앉힌 선수 |
|---|---|
| arg | E.마르티네스(23) · 맥알리스터(20) · 라우타로(22) · 엔소(24) · 로메로(13) · 몰리나(26) |
| fra | 마이냥 · 음바페 · 추아메니 · 살리바 · 테오 에르난데스 |
| nor | **홀란** · 외데고르 |
| ecu | **M.카이세도** · 파초 |
| esp | 우나이 시몬 · 페드리 · 야말 · 쿠쿠레야 |
| can | 조너선 데이비드 · 에우스타키우 |
| kor | 이강인 · 황인범 · 설영우 |

각 팀 `profile.signatureXI`에 **그 팀의 선발 11명이 이미 적혀 있었으나** 저장소 어디서도
읽지 않는 죽은 데이터였다(`grep -rn signatureXI src/ tools/ api/` → 소비처 0곳).

**처방**: `tools/team-balance/reorder.mjs`가 squad 배열을 `signatureXI` 기준 뎁스 차트순으로
다시 적는다. 능력치는 한 점도 건드리지 않는다. 선수 한 명이 정확히 한 줄이므로 **줄만 재배열**해
원본 서식을 보존한다.

> **엔진 쪽 권고(이번 작업 범위 밖)**: 근본 해법은 `pickBestXI`가 `signatureXI` 또는 자질을
> 참조하는 것이다. 데이터 정렬은 같은 효과를 내지만, 팀의 실제 형태가 엔진의 6종 포메이션에
> 없을 때는 순서로 뒤집을 수 없다 — 아래 3절.

### 2.1 순서로 고칠 수 없는 잔여 — 포메이션 매핑

탐욕 선정은 슬롯을 앞에서부터 채우고, 각 슬롯은 **정포지션(1.0)이 대체 포지션(0.85)을 항상 이긴다.**
그래서 팀의 실제 형태에 그 슬롯이 없으면 그 선수는 배열 순서와 무관하게 탈락한다.

- `nor` 외데고르(AM) — 4-1-4-1에 AM 슬롯이 없다
- `kor` 이강인(AM) — 4-2-3-1의 RW를 자연 RW가 가져간다
- `cze` 코우팔(RB) — 3-5-2에 RB 슬롯이 없다

이 셋은 데이터로 고치지 않고 남겼다.

## 3. 팀별 재보정

각 팀의 `statBaseline.source`에 어떤 축을 왜 몇 점 바꿨는지 문장으로 기록했다.
`profile.styleNotes`가 선언한 정체성을 지키는 축만 건드렸다.

| 팀 | 랭킹 | 바꾼 것 | 정체성 보존 |
|---|---|---|---|
| arg | 1 | 선호 포메이션 4-2-2-2→**4-3-3** · GK/CB/중원/전방 소폭 상향 · 슛 12.7→15.4 | 점유·템포 무변경 |
| esp | 2 | 없음(배열 순서만) | — |
| fra | 3 | 슛 17.0→14.4 · 바르콜라·위파메카노·테오 조정 | 음바페·뎀벨레·마이냥 무변경 |
| eng | 4 | 없음(배열 순서만) | — |
| mar | 7 | 슛 8.0→12.6(유효율 43.7% = 12팀 최고) · 후방·전방 결정력 상향 | **볼륨이 아니라 질**로 올렸다 |
| mex | 14 | 중앙수비·결정력 상향 · 슛 12.0→13.2 | 단일 피벗 무변경 |
| ecu | 23 | 선호 포메이션 4-2-2-2→**4-2-3-1**(더블 피벗 복원). 능력치 무변경 | 결정력 약점 그대로 |
| can | 30 | 중원·후방·최전방 상향 | 데이비스 무변경 |
| nor | 31 | 측면·후방·GK 하향 | **홀란·외데고르 한 점도 안 건드림** |
| cze | 40 | 백3 수비 상향 · 유효슛 2.5→3.2 | 중앙 창의성 그대로 |
| rsa | 60 | 없음(배열 순서만) | — |

### 3.1 정체성이 방향을 정한 두 사례

**모로코** — `styleNotes`가 "적은 슈팅으로 득점하는 효율 극대화가 정체성"이라고 못 박았다.
그래서 볼륨을 크게 올리는 대신 **슛 하나의 값**을 키웠다. 12.6은 한국(13.0)·멕시코(13.2)·
에콰도르(13.3)보다 여전히 적고, 유효슈팅 5.5/12.6 = **43.7%로 12팀 중 최고**가 된다.
"적은 슈팅·높은 효율"이 이제 수치로 정확히 표현된다.
(8.0은 벨기에·스페인·포르투갈·프랑스를 상대로 저블록을 세운 카타르 월드컵 녹아웃 4경기가
눌러 놓은 표본이었다.)

**노르웨이** — `styleNotes`가 "홀란 의존도가 구조적으로 매우 크다"고 선언했다.
31위로 내리면서 홀란(shooting 92)과 외데고르는 **한 점도 건드리지 않고** 주변만 내렸다.
의존도 정체성은 오히려 강해진다.

## 5. 남긴 것

- **상위 4팀이 18~26%로 목표 대역(20~30%) 아래에 걸친다.** 스페인·프랑스를 20%대 후반까지
  올리려면 유로 2024 우승 스쿼드와 프랑스 백4를 랭킹 근거 없이 깎아야 한다. 역전이 없는 쪽을
  택했다.
- **can(45%) vs nor(43%)** — 2%p 역전이 남았다. 판정 마진 3%p 안이고 SE의 2.5배 미만이다.
- 위 2.1의 포메이션 매핑 잔여 3건.
- **시드 1057은 병리적이다.** 재보정 **전에** 이미 26,400경기 중 11경기가 두 자릿수 스코어였고
  전부 시드 1057이었다(fra-rsa 11-0 · esp-cze 12-0 포함). `realdata-calibration.test.ts`의
  "팀당 0~9골" 게이트는 esp-arg 한 매치업만 보는데, 팀 전력이 조금만 움직여도 이 한 경기가
  9↔10을 넘나든다. **엔진 쪽에서 시드 1057의 난수 계열을 들여다볼 값어치가 있다.**
