## 0. 한 장 요약

이 게임은 **"경기 중 감독"으로는 이미 상당한 깊이**를 갖췄다(개입 3+n회, 멘탈리티·4축·그룹 적극성·공격 패턴·페이즈 포메이션·GK 파워플레이·코치 회의·팀토크·외침). 문제는 그 깊이가 **킥오프 이후에만 존재**한다는 것이다.

실플레이로 확인한 현재 경기 전 플로우:

```
허브(상대 카드: 이름·FIFA랭킹·선호포메이션·styleNotes 3줄)
  → 라인업 화면(포메이션 6버튼 + 11인 DnD + 벤치 15장)  ← 여기가 전부
  → 킥오프 화면(버튼 1개)
  → 22' 첫 하이드레이션 브레이크에서 비로소 전 전술 옵션 개방
```

즉 **유저는 22분간 라인 50 / 압박 50 / 템포 50 / 균형 멘탈리티라는 "무색 자동 조종" 상태로 경기를 관전한 뒤에야 감독이 된다.** 사용자 지적 "구체적인 전술을 이때부터 만들 수 있어야지"는 정확한 진단이며, 이것이 이 감사의 1순위 항목이다.

동시에, 실측 시뮬로 **더 심각한 구조 문제**를 발견했다: 지시 4축 중 **라인 높이와 압박은 낮을수록 무조건 유리한 단조 함수**다(§10). 전술 센터를 만들어 옵션을 전부 노출해도, 그 옵션 공간의 최적해가 "다 내려라" 하나뿐이면 전술 게임이 성립하지 않는다. **전술 센터(UI)와 축 밸런스(엔진)는 반드시 같이 가야 한다.**

3대 결론:
1. **경기 전 전술 센터**를 신설한다 — 라인업 화면을 4탭 워룸으로 확장하고, 좌측에 상대 리포트를 상시 병치한다(§3).
2. **지시 축에 상향 보상을 부여**해 단조 지배 전략을 제거한다 — 그래야 전술 센터의 선택이 의미를 갖는다(§10).
3. **상대 AI를 움직이게 한다** — 현재 상대는 90분간 교체 0회·지시 변경 0회의 정지 상태다. 체감 지능 대비 비용이 가장 싼 항목이다(§7).

## 2. 감사 중 발견한 구조적 결함 3가지 (요약)

1. **비대칭 시작 조건** — AI는 프로필 스타일을 지시로 갖고 출전(`defaultTactics`), 유저는 항상 50/50/50. 유저가 22분간 불리하게 시작한다.
2. **플라시보 3종** — `morale`(엔진 미참조), `setPiece`(전역 미참조), `foot`(전역 미참조). UI에서 보여주고 조작하게 하는데 결과에 영향이 없다. 감독 경험 설계 배점(25) 심사에서 "인과 가시성"(스펙 §4 마지막 문단)을 정면으로 위배한다.
3. **정지한 상대** — 상대 감독은 존재하지 않는다. 90분 동안 아무 결정도 하지 않는다.

## 3. ★ 경기 전 전술 센터 — 상세 설계

### 3.1 설계 원칙

1. **동일 컨트롤 재사용** — 경기 전과 경기 중은 *같은 전술 언어*를 쓴다. 새 컴포넌트를 만들지 않고 `ConsolePanel` / `TacticsExtras` / `OppPanel`을 그대로 쓴다. 유저는 한 번 배운 UI를 두 시점에서 쓴다(학습 비용 0).
2. **상대와 나란히** — 전술 결정의 근거는 상대다. 탭으로 숨기지 않고 **좌측 고정 컬럼**에 상대 리포트를 상시 노출한다(fm-matchday §5.1 스카우트 리포트).
3. **선택에 즉시 예측 피드백** — 컨트롤을 움직이면 하단 "우리 플랜" 카드가 즉시 갱신되고, 리스크 배지가 뜬다(fm-matchday 핵심 이식 원칙 2 "모든 개입에 즉각 가시 피드백").
4. **사전 설계에 게임 이론적 보상** — 계획 유지 보너스 / 이탈 적응 지연(§3.7). 이게 없으면 유저는 전술 센터를 스킵하고 하프타임에 몰아 처리한다.

### 3.2 정보구조 — "단계"가 아니라 "탭"

**결론: 탭.** 근거:
- 단계(위저드)는 뒤로 가기가 필요하고, 상대 리포트를 계속 참조하는 흐름과 충돌한다.
- 4탭 중 **①선발과 ②팀 전술만 필수**, ③개인 지시·④세트피스는 선택(기본값으로 완주 가능) → 위저드로 강제하면 3분 온보딩(스펙 §3.1)이 깨진다.
- 이미 경기 중 작전판이 3탭(전술/교체/상대) 구조라 일관성이 있다.

**진입 게이팅**: 없음. 킥오프 버튼은 언제나 활성. 단 미완 항목(세트피스 키커 미지정 등)은 하단 요약에 노란 배지로만 표시한다. 심사자 3분 경험을 막지 않는다.

- 저장소: `localStorage['rematch-tactic-presets']`, 최대 5슬롯. 실패(사파리 프라이빗 등)는 조용히 무시(현행 `read3dPref` 패턴 준용).
- **번들 프리셋 3종**(코드 상수, 삭제 불가):

  - **점유 압박** — 4-3-3 / 공격 / 라인 60·압박 60·템포 45 / 균형 / 공격 적극 → *"약팀 상대"*
  - **균형** — 4-2-3-1 / 균형 / 50·50·55 / 균형 → *"기본"*
- 불러오기 시 lineup 검증: 없는 선수·GK 슬롯 비GK는 `autoFill`로 자동 보정하고 "3명 자동 보정됨" 토스트.

### 3.7 ★ 경기 전 계획 vs 실전 괴리 (플랜 이탈 메커닉)

**문제**: 하프타임에 전부 바꿀 수 있다면 킥오프 전 설계는 게임 이론적으로 무의미하다. 유저는 전술 센터를 스킵하는 게 최적 플레이가 된다.

**해법**: 킥오프 시점의 플랜을 스냅샷으로 잠그고, 유지/이탈에 각각 값을 매긴다.

```ts
// matchStore
matchPlan: TacticState | null   // kickoff() 시점 스냅샷
planDeviation: number           // 플랜 대비 변경 축 수(누적 최대치)
```

1. **팀 이해도 보너스(유지 보상)** — 킥오프 플랜의 멘탈리티·포메이션이 유지되는 동안 `chanceQuality × 1.03`. 90분 완전 유지 시에만 최대. 값은 작게(3%) 두되 **UI에 명시**한다: 스코어버그 옆 "플랜 유지 ✅ 팀 이해도 +3%".
2. **적응 지연(이탈 비용)** — 포메이션 또는 멘탈리티를 바꾸면 **직후 3분간** `chanceRate × 0.94`, `counterVulnerability × 1.06`. 기존 "개입 직후 8분 부스트 ×1.3"과 **정면 상충하지 않게** 설계: 부스트는 *지시 미세조정*(4축)에만, 지연은 *구조 변경*(포메이션·멘탈리티)에만 적용한다.
   → "미세 조정은 즉효, 구조 변경은 대가가 있다"는 FM의 감성(fm-matchday §2.1 "조작한 변경은 즉시 반영되지 않고 이후 국면부터 서서히")을 규칙화.
3. **개입 창 상단 "플랜 대비" 배지** — `계획: 압박 40 → 현재 75 (+35)` 형태로 이탈 축을 나열. 유저가 자기 계획으로부터 얼마나 멀어졌는지 항상 보인다.
4. **기자회견 연결** — `planDeviation`을 `pressconf.buildQuestions`의 분기 입력으로 추가.
   - 이탈 0 & 승리 → "계획대로 됐습니다. 무엇을 준비했습니까?"
   - 이탈 4+ & 승리 → "전반과 완전히 다른 팀이었습니다. 원래 계획이 틀렸던 겁니까?"
   - 이탈 4+ & 패배 → "계획을 버린 것이 패인이었다고 보십니까?"
   → **경기 전 설계가 경기 후 서사로 회수된다.** 참신성(30점) 항목의 "AI 기자회견" 가치가 증폭된다.

이 4개가 함께 있어야 "감독은 킥오프 전에 계획을 세우고, 경기가 계획을 시험한다"는 루프가 닫힌다.

### 3.8 엔진 연결

**핵심 아이디어: 전술 센터를 새 화면이 아니라 `phase: 'pre'`의 작전판으로 구현한다.**

현재 `ConsolePanel` / `TacticsExtras` / `SubPanel` / `OppPanel`은 전부 `useMatchStore(s => s.engine)`을 읽고 `open = phase ∈ {halftime, paused-*}`로 게이팅한다. 경기 전에는 `engine`이 없어 그대로는 못 쓴다. 두 경로:

| 경로 | 내용 | 비용 | 평가 |
|---|---|---|---|
| A. 컴포넌트 prop화 | 각 패널이 `tactics + onChange`를 받고 store 바인딩은 얇은 래퍼로 | 4개 컴포넌트 시그니처 변경 + 테스트 갱신 | 깨끗하지만 마감 대비 비쌈 |
| **B. `'pre'`를 개입 phase로 승격** ★권고 | 전술 센터 진입 시 `startMatch()`를 먼저 호출해 엔진을 `'pre'`로 생성 → `INTERVENTION_PHASES`에 `'pre'` 추가 → 기존 패널이 **무수정으로 동작** | `matchStore.ts` 상수 1줄 + 각 패널 `open` 조건 1줄 × 4 + 화면 조립 | 최소 변경, 경기 전/중 UI 완전 일치 |

**경로 B 상세**

```ts
// matchStore.ts
const INTERVENTION_PHASES: MatchPhase[] = ['pre', 'paused-break', 'paused-user', 'paused-moment', 'halftime']
```

- **결정 로그**: `submitCommand`가 `minute = 0`으로 기록 → 요약 라벨만 `킥오프 전`으로 분기(현행 `halftime → 'HT'` 분기와 동일 패턴). 이로써 **킥오프 전 결정도 기자회견 근거가 된다**(스펙 §7 "내 결정 로그 기반 추궁").
- **부스트 금지**: `confirmTactics`는 `'pre'`에서 `boostUntil`을 설정하지 않는다(사전 계획에 인게임 부스트를 주면 §3.7의 균형이 깨짐). `kickoff()`가 `matchPlan` 스냅샷을 찍는다.
- **App 흐름 변경**:
  ```
  현재: HubScreen → LineupScreen(로컬 TacticState) → MatchScreen(startMatch)
  변경: HubScreen → MatchScreen(mount 즉시 startMatch, phase 'pre')
                     └ phase==='pre' → TacticsCenter 렌더(방송 스테이지 위)
                     └ [킥오프] → kickoff() → 기존 broadcast 흐름
  ```
  `LineupScreen`은 "①선발 탭"으로 흡수되며, `initial`/`onConfirm` 대신 store를 읽고 `submitCommand({type:'formation'})`로 쓴다(현행 `TacticsBoard.changeFormation`과 동일).
- **A3 결함 자동 해소**: TacticState를 통째로 store에 두므로 확장 필드 유실이 원천 차단된다.
- **A4 이월 자동 해소**: `App`의 `tactics` 로컬 state 제거. 이월은 `campaignStore.lastTactics`(신규 필드)에 확정 플랜을 저장하고 다음 경기 `startMatch(opts.homeTactics)`로 주입.
- **A2 해소**: 첫 진입 기본값을 `pickBestXI`의 `{50,50,50}`이 아니라 `kor.profile.style`(점유60·압박62·라인50·템포55)로 시딩 — AI와 대칭. 그 위에 `recommendPlan`이 상대별로 조정.

**타입 확장(전부 optional — 시드 회귀 불변 원칙 유지)**


|---|---|---|

## 4. 선수 개인 지시 — 설계

§3.4 ③탭 + §3.8 타입/훅 참조. 추가 결정 사항만 기록.

- **역할은 데이터가 아니라 지시다.** `Player.role`을 JSON에 넣지 않는다. 312명 × 역할 부여는 검수 비용이 크고, 무엇보다 *유저가 정하는 것*이어야 감독 경험이 된다. `TacticState.playerRoles`에 둔다.
- **적합도 5성** = `positionFitness(player, slot) × Σ(역할 핵심 스탯 / 100 × 가중)`을 0~5로 양자화. 예: `target-man` = physical 0.4 + shooting 0.3 + pace 0.1 + passing 0.2.
- **역할 배수는 작게** — 존 전력 ±6% 이내. 스펙 §6.2 "포메이션이 전부가 되지 않게" 원칙(리서치 §3.1 마지막 문단)을 역할에도 적용. 선수 개인 스탯이 주도권을 유지해야 한다.
- **경기 중에도 변경 가능** — ③탭을 작전판(경기 중)에도 동일하게 추가. 마킹 대상 변경은 하프타임 개입의 강력한 카드가 된다("소우체크에게 이기혁을 붙인다").

## 5. 세트피스 — 설계

§3.4 ④탭 + §3.8 서브롤 참조. 추가 결정 사항.

- **코너 전환율 목표: 코너당 6~9%**. 리서치 §1.13(무페널티 득점의 25%가 세트피스)을 참조하되, 현재 코너 발생량(경기당 5~7개)에서 세트피스 골이 경기당 0.35~0.6골이 되도록 캘리브레이션한다. 기존 `calibrate.ts` 계약(shots/xG ±15%)을 깨지 않으려면 세트피스 골도 `stats.shots`·`xg`에 함께 계상해야 한다.
- **루트별 성격**:
  | 루트 | 배수 | 성격 |
  |---|---|---|
  | 니어 | 전환 ×1.15, 역습 실점 ×1.10 | 고위험 고수익 |
  | 파 | 전환 ×1.00, 역습 실점 ×1.00 | 표준 |
  | 숏 | 전환 ×0.75, 역습 실점 ×0.80, 점유 유지 | 안전 |
- **박스 투입 인원**(light/normal/heavy): heavy는 전환 ×1.2 / 이 분 상대 역습 `counterVulnerability ×1.25`. **GK 파워플레이의 축소판**을 매 코너마다 제공하는 셈 — 이미 검증된 트레이드오프 패턴 재사용.
- **수비 마킹(존/맨)**: 상대 키플레이어 aerial 평균이 높을 때 맨이 유리, 낮을 때 존이 유리 — 상대 프로필을 읽어야 정답이 갈리는 구조로 만든다(전술 센터 좌측 리포트와 직결).
- **`setPiece` 스탯 활성화**가 이 항목의 진짜 가치다. 312명 검수 완료된 데이터가 지금 완전히 죽어 있다.

## 6. 선수단 관리 깊이 — 설계

마감(8/3)을 고려한 **선별 도입** 권고.

| 항목 | 권고 | 설계 |

## 7. 상대 AI 지능 — 설계

**현재 격차**: FM은 어시스턴트 조언 + 상대 OI + 인게임 스위칭을 갖는다(fm-matchday §2.4, §5.2). 우리 상대는 **완전 정지**다. 이 항목은 **비용 대비 체감 효과가 이 문서에서 가장 크다.**

### 7.1 AI 교체 (`benchPattern` 활성)

`matchStore.advanceMinute` 안에서 매 분 순수 함수 호출:

```ts
// game/oppAi.ts (신규, 순수·결정론)
export function decideAwaySubs(st: MatchState, minute: number): MatchCommand[]
```
규칙:
- 창: 46' / 60' / 70' / 80' 중 조건 충족 시 (경기당 최대 3~4장, 유저 5장보다 적게 — 유저 우위 유지)
- `protect-lead` & 리드 중 → 공격수 OUT / 수비수·DM IN + 지시 라인 −15
- `chase-attack` & 지고 있음 → 수비수 OUT / 공격수 IN + 멘탈리티 `attacking`
- `balanced` → 체력 최하위 2명 교체
- 대상 선정은 `staminaByPlayer` 최하위 + `positionFitness`로 결정론 선택 (RNG 불필요 → 회귀 안전)

### 7.2 AI 인게임 전술 스위칭 (프로필 범위 내)

```ts
export function decideAwayTactics(st: MatchState, minute: number): TacticState | null
```
- **프로필 범위 클램프**가 핵심(스펙 §6.2 "프로필 범위 안에서만"): 각 축은 `profile.style.X ± 20` 밖으로 못 나간다. → 스페인은 끝까지 점유를 고집하고, 모로코는 리드하면 더 내려앉는다.
- 트리거: 리드 획득(라인 −12, 멘탈리티 한 단계 수비적) / 실점(라인 +10, 멘탈리티 한 단계 공격적) / 75' 이후 무승부(추격 성향에 따라) / 상대 압박에 점유 40% 미만 15분 지속(템포 +10).
- 유형당 1회 제한 → 과잉 변동 방지(`firedMoments` 패턴 재사용).

### 7.3 상대 전술 변경 통보

- 방송 배너(현행 `ms-banner` 재사용): `📢 체코, 5백으로 내려섭니다` / `📢 체코 교체 — 시크 OUT, 호리 IN`
- 작전판 상대 탭 상단에 "변경 이력" 타임라인 3줄.
- fm-matchday §5.2는 FM에도 명시 알림이 확정적이지 않다고 기록하지만, **웹 게임에서는 명시 통보가 옳다** — 유저에게 "상대 감독이 살아있다"를 증명하는 유일한 창구이기 때문. 스펙 §17.5도 명시 요구.

### 7.4 어시스턴트 실시간 토스트

- 재생 중 1줄 토스트(`coach.buildCoachAdvice`의 근거 생성 로직 재사용, 제안 없이 관찰만): "우리 유효슛이 12분째 없습니다", "상대 코너가 5개째입니다".

### 10.1 측정 방법

`createMatch` + `simulateSegment(…, 90)` 배치, 시드 1000..N 고정. 홈=대한민국(전 케이스 `pickBestXI` 4-2-3-1 XI 고정), 어웨이=AI 기본. 각 셀 250~400경기.

### 10.3 진단 — 🔴 단조 지배 전략

1. **라인 높이는 단조 감소.** 상대가 강할수록 기울기가 가팔라진다(스페인전 10 vs 90 = 12pp 차). **하이라인이 유리한 상황이 하나도 없다.**
   원인: `instructionEffects`에서 라인의 상승 이득은 `chanceQuality lerp(0.945→1.055)` (±5.5%)뿐인데, 비용은 `counterVulnerability lerp(0.75→1.25)` (±25%)다. **비용이 이득의 4.5배**이고, 후자는 상대 찬스 확률에 직접 곱해진다.
2. **압박은 더 심하다.** 70 이상에서 절벽(체코전 −12.8pp, 스페인전 −9.6pp). 압박의 이득은 `chanceRate ×1.1` 하나인데, 비용은 `counterVulnerability ×1.075` + `foulRate ×1.225` + `staminaDrain ×1.26` + 지속압박 페널티(10분마다 체력 −15% 가중, 저체력 시 압박 실효 반감 + 파울 1.5배)까지 **4중 누적**된다.
3. **템포만 유일하게 밋밋** — ±3pp 안. 즉 4축 중 사실상 **2축은 "내려라"가 정답, 1축은 무의미, 1축(공격방향)은 엔진 미반영**(`attackFocus`는 `instructionEffects`에서 읽지 않음 — 순수 표시용).
4. **결론: 지시 4축은 현재 "다 낮춰라" 1차원 퍼즐이다.** 전술 센터로 이 축들을 킥오프 전에 전부 노출하면, 숙련 유저는 5분 안에 최적해를 찾고 이후 전술 결정이 사라진다. 심사자가 발견할 위험도 실재한다.

### 10.5 유저 개입의 승률 기여도 (A/B 실측)

"숙련 감독 플랜"(라인 20·압박 25·템포 80 / 상대별 멘탈리티 / 중앙 침투 / 공격 그룹 적극) vs 기본값:

| 상대 | 무개입 | 숙련 플랜 | Δ | +개입 부스트 상시 적용 |
|---|---|---|---|---|
| 체코 | 54.0% | 63.5% | **+9.5pp** | 65.0% (+1.5pp) |
| 멕시코 | 45.0% | 56.5% | **+11.5pp** | 57.0% (+0.5pp) |
| 스페인 | 28.7% | 39.5% | **+10.8pp** | 36.5% (**−3.0pp**) |

진단:
- **전술 선택의 총 레버리지는 +10pp 수준** — 방향은 맞지만, 그 10pp의 대부분이 §10.3의 단조 최적해에서 나온다. 즉 "잘 고른 것"이 아니라 "다 내린 것"의 보상이다.
- **개입 직후 부스트(×1.3, 8분)는 사실상 무효과** (+0.5~1.5pp, 스페인전은 오히려 −3pp). 스펙 §17.1 "개입 직후 5~10분 지시 효과 부스트 — 변화가 체감되게"의 의도가 수치로 달성되지 않았다.
  원인: `amp(v) = 1 + (v−1)×1.3`은 지시가 중립(1.0)에 가까울수록 아무 일도 안 하고, 저압박·저라인 플랜에서는 **1.0 미만 편차까지 증폭**해 역효과를 낸다.
  **처방**: 부스트를 방향 증폭이 아니라 **명시적 보너스**로 바꾼다 — 개입 후 8분간 `chanceQuality ×1.08` + `counterVulnerability ×0.94` 고정. 값이 항상 같은 방향이라 UI로 약속할 수 있고("작전 지시 효과 8분간 지속"), 실제로 체감된다.
- **개입 A/B 상시 계측 제안**: `calibrate.runBatch`를 확장한 `runAbBatch(baseTactics, planTactics, n)`을 테스트로 상주시키고, **`Δ ≥ 8pp`를 회귀 게이트로 고정**한다. 엔진 수정 시 "유저 개입이 무의미해지는" 퇴행을 자동 감지한다.

### 10.6 개별 배치의 처벌 강도 (실측)

| 케이스 | vs 체코 승률 | 기준 대비 |
|---|---|---|
| 정상 XI | 54.0% | — |
| 손흥민(LW) ↔ CB 스왑 | 18.5% | **−35.5pp** |
| GK 슬롯에 조규성(ST) | 41.3% | −12.7pp |

- 필드 미스매치 처벌은 **충분히 강하다** → §1.2 B5(추가 실수 확률)는 컷 가능.
- **GK 미스매치가 필드 미스매치보다 약한 것은 명백한 결함** → §1.2 B6 수정 필요. 스펙 §6.1은 "파국적"을 요구한다.

### 10.7 알려진 경계값

- `esp(home) vs kor(away)` 양측 AI 기본: **esp 승률 51.2% / 무 20.0%** (400경기). P2B Task 2에서 세운 게이트 `esp ≥ 50`을 **1.2pp 차로 통과** — 통계적으로 취약하다. §10.4 엔진 수정 후 반드시 재측정하고, 게이트를 `esp ≥ 55`로 상향해 여유를 확보할 것을 권고한다(현재 값은 랭킹 1위 팀이 랭킹 20위권 팀에 반반이라는 뜻).
- **홈 어드밴티지 미모델링**: `kor(home) vs esp` 28.7% / `esp(home) vs kor` 로 본 kor 28.8% — 완전 대칭. 월드컵 중립 경기장 설정이라 의도로 볼 수 있으나, 캐나다·멕시코전은 실제 홈이므로 `+3%` 정도의 서사적 홈 보정을 검토할 여지가 있다(우선순위 낮음).
