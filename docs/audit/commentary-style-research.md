# 한국 축구 중계 화법 리서치 → 템플릿 설계

## 0. 현재 코드 진단 요약 (읽은 것: `src/game/commentary.ts`, `src/audio/commentary-tts.ts`)

26개 템플릿 전부가 **`{분}' ` 접두 + 종결어미 `-니다`** 구조. 화자 1명. 이벤트 히스토리 없음. 변형 선택자가 `(minute * 31 + type.length) % n`인데 `type.length`는 타입별 상수이므로 사실상 `minute % n` — **2변형이면 짝/홀 분에 엄격 교대(ABAB), 3변형이면 ABCABC**. 이건 랜덤보다 나쁘다(지각 가능한 주기). 이 4가지가 로봇처럼 들리는 원인의 90%다. 상세는 §4.

## 1. 캐스터 vs 해설위원 역할 분담

### 1.1 담당 영역

| | 캐스터 (play-by-play) | 해설위원 (analyst) |
|---|---|---|
| 말하는 시점 | 공이 살아있는 동안 (실시간) | 공이 죽은 뒤 / 리플레이 위 |
| 담당 정보 | 누가·어디서·무엇을 (WHAT) | 왜·어떻게·다음은 (WHY) |
| 문장 길이 | 1~4어절 버스트 ~ 1문장 | 1~3문장, 5~15초 |
| 종결 | `-습니다/-ㅂ니다`, 체언 종결 | **`-죠`**, `-네요`, `-거든요`, `-고요` |
| 인칭 | 3인칭 서술 | 1인칭 판단 ("제가 보기엔", "저는 ~라고 봅니다") |
| 숫자·기록 | 분·스코어·통산 기록·교체 번호 | 거의 안 씀 |
| 감정 | 흥분(고음·고속) | 탄식·감탄(저음·완서) "아이고", "어허" |

핵심: **캐스터는 사실을 던지고, 해설은 그 사실에 인과를 붙인다.** 해설은 절대 먼저 말하지 않는다 — 항상 캐스터의 마지막 문장을 받아서 시작한다.

### 1.2 턴 전환 마커 (템플릿화 가능)

**해설 오프너 (거의 항상 이 중 하나로 시작)**
```
네,  /  예,  /  그렇죠.  /  맞습니다.  /  아이고…  /  어허…
이게  /  이 장면은  /  지금  /  여기서  /  사실
아까도 말씀드렸는데  /  제가 보기엔  /  저는 이렇게 봅니다
```

**해설 클로저**
```
~거든요.  ~죠.  ~네요.  ~고요.  ~입니다.  ~라고 봅니다.  ~같아요.
```

**캐스터가 해설에게 넘기는 훅**
```
위원님, 어떻게 보셨습니까?
이거 파울인가요?
이 장면 다시 한번 보시죠.
지금 저 교체, 어떤 의미일까요?
{해설이름} 위원?
```

**캐스터가 다시 받는 마커** — 해설 발언 뒤 경기 재개 신호
```
자,  /  네, 그렇군요.  /  경기 재개됩니다.  /  다시 공이 굴러갑니다.
```

### 1.3 실전 페어 6종

표준 시퀀스는 4박자다: **[캐스터 피크] → [캐스터 사실 앵커] → [해설 인과] → [캐스터 재개]**. 게임에서는 앞 3박자만 쓰면 된다.

**① 골**
> **캐스터:** 손흥민! 들어갑니다! 골!! 골!! 대한민국 앞서 나갑니다!
> **캐스터:** 전반 27분, 손흥민의 선제골입니다.
> **해설:** 네, 이게 앞선 상황에서 이강인이 한 박자 늦게 내준 게 컸어요. 수비수 두 명이 다 공만 보고 있었거든요. 그 순간에 뒤로 빠졌고요. 저건 못 막습니다.

**② 결정적 세이브**
> **캐스터:** 슛! …아, 막았습니다! 조현우! 조현우가 막아냅니다!
> **해설:** 아이고… 이거 방향을 읽었다기보다 반응으로 막은 거예요. 발이 먼저 나갔죠. 저 거리에서 저건 진짜 대단한 겁니다.

**③ 빗나간 슛**
> **캐스터:** 때립니다! …아아, 아쉽습니다. 골대 옆으로 살짝 빗나갑니다.
> **해설:** 네, 조금만 더 눕혀서 찼으면 좋았을 텐데요. 몸이 뒤로 젖혀졌어요. 그래도 저 위치에서 슛을 선택한 건 맞습니다.

**④ 경고**
> **캐스터:** 아, 주심이 카드를 꺼냅니다. 옐로카드. 김민재, 경고 받습니다.
> **해설:** 음… 발이 먼저 들어간 건 맞아요. 다만 김민재 선수 이제 조심해야 됩니다. 하나 더 받으면 다음 경기 못 나오거든요.

**⑤ 교체**
> **캐스터:** 자, 교체 준비합니다. 4번 이강인 나가고, 14번 홍현석 들어갑니다.
> **해설:** 이 교체는 예상됐던 거죠. 이강인 선수 활동량이 많았고, 상대가 스리백으로 바꾸면서 중앙이 좁아졌거든요. 폭을 좀 넓히겠다는 의도로 보입니다.

**⑥ 전술 변화**
> **캐스터:** 그런데 대한민국, 지금 라인이 눈에 띄게 올라와 있죠?
> **해설:** 네, 후반 시작하면서 확실히 올렸습니다. 전반엔 미드필드 라인이 하프라인 아래였는데 지금은 거의 상대 진영에서 압박하고 있어요. 위험 부담은 있지만, 한 골 넣어야 하는 상황이니까 맞는 선택이라고 봅니다.

**게임 적용 규칙:** 해설 라인은 **모든 이벤트에 붙이지 말 것**. 실제 방송도 해설이 개입하는 건 이벤트의 30~40%다. 붙일 조건 — `goal`, `red`, `sub`, 전술변경, `save`(중요도 高), 그리고 소강 상태 90초 경과 시 채우기용.

### 2.x 특징적 장치 6종 (템플릿 문법으로 구현할 것)

| 장치 | 형태 | 사용 조건 | TTS 안전? |
|---|---|---|---|
| **체언 종결** | `슛!` `골!` `옐로카드.` `코너킥.` | 피크 순간, intensity ≥ 2 | ✅ |
| **현재형 진행** | `들어갑니다` `때립니다` `돌아섭니다` `올라옵니다` | 캐스터 기본형. **모든** 동작 서술 | ✅ |
| **감탄 어미** | `~네요` `~군요` `~죠` `~는데요` | 해설 전용. 캐스터는 `~습니다!` | ✅ |
| **반복·연호** | `{선수}! {선수}!` (2~3회) | 골·결정적 세이브만. 1경기 3회 상한 | ✅ |

## 3. 맥락 인지 화법 — 핵심 섹션

### 3.1 스코어 상황 (골 종류 판정)

한국어는 골 종류마다 **전용 명사**가 있고, 중계는 이걸 틀리면 즉시 어색해진다. 현재 코드의 `goal` 템플릿 3개는 이 축이 전혀 없다.

**판정 로직** — 득점팀 관점, 골 **직전** 스코어 기준:
```
diff = 득점팀점수 - 상대점수  (골 넣기 전)
total = 두 팀 합계 (골 넣기 전)
wasBehind = 이 경기 중 한 번이라도 뒤진 적 있는가 (플래그 필요)

total == 0                      → 선제골 (= 선취골)
diff == -1                      → 동점골
diff ==  0 &&  wasBehind        → 역전골
diff ==  0 && !wasBehind        → 결승골 후보 / "다시 앞서 나가는 골"
diff <= -2                      → 추격골 (늦고 큰 점수차면 만회골)
diff >=  1 && (diff>=2 || 분>=75) → 쐐기골
diff >=  1                      → 추가골
+ 후처리: 분 >= 88 && (동점골|역전골|결승골) → 극장골 오버레이
+ 득점자 이 경기 2번째 → 멀티골 / 3번째 → 해트트릭
+ 자책 → 자책골 (특수 톤: 흥분 금지)
```

**문장 패밀리**
```

### 3.5 전술 지시 반영 — 매니저 게임의 핵심 차별점

플레이어가 지시를 내리면 **해설위원이 그 지시를 알아본다.** 이게 "내 지시가 세계에 반영됐다"는 감각을 만든다. 각 지시마다 **효과 있음 / 역효과 / 유보** 3분기를 두고, 실제 시뮬 결과와 연동.

```

  역효과: 라인을 올렸는데, 저 뒷공간이 계속 걱정됩니다.
  유보: 라인을 확실히 올렸습니다. 위험 부담은 감수하겠다는 거죠.

압박 라인 ↓
  효과: 내려서니까 확실히 안정됐습니다. 실점 위험이 줄었어요.

|---|---|---|---|---|
| 1 | **분 접두 100%** | 26/26 템플릿이 `` `${m}' ` `` 로 시작 | 실제 캐스터는 분을 10줄에 1번, 그것도 골·카드·전후반 경계에서만 말한다. 매 줄 시간 낭독은 스코어보드지 중계가 아니다 | 분을 문장에서 분리해 UI 크롬(타임스탬프 컬럼)으로. 문장 안 삽입은 `goal`/`yellow`/`red`/`halftime`/`fulltime` + 그 외 20% 확률. 삽입 시 형식은 `전반 27분` (§5) |
| 2 | **종결어미 단일** | 26/26이 `-니다`/`-입니다` | 실제 피크는 체언 종결 — `슛!` `골!` `옐로카드.` | 레지스터별 종결 풀: fragment / -니다 / -네요 / -죠 |
| 3 | **문장 길이 균일** | 전 템플릿 12~18음절 | 리듬이 없다. 실제는 2음절 버스트와 40음절 분석이 교차 | 길이 클래스 `burst(1-4) / short(5-15) / mid(16-30) / long(31+)`. 직전 라인과 같은 클래스 연속 2회 금지 |
| 4 | **변형 선택자가 주기적** | `(minute*31 + type.length) % n`, `type.length`는 타입 상수 → 실질 `minute % n` | 2변형이면 짝/홀 분 엄격 교대. 유저가 3분이면 알아챈다. 랜덤보다 나쁨 | FNV-1a 등 실제 믹서로 `hash(matchSeed, minute, type, playerId, score, eventIdx)`. + **최근 N개 사용 변형 억제 링버퍼** |
| 5 | **직전 사건 무기억** | `commentate(e, home, away)` — 히스토리 파라미터 없음 | `또`, `이번에도`, `벌써`를 절대 말할 수 없다. **가장 큰 로봇 신호** | 시그니처를 `commentate(e, ctx)` 로. `ctx`에 `recentEvents`, `score`, `wasBehind`, `streaks`, `flow`, `lastLineIds` |
| 6 | **필러·접속 부재** | 0개 | 실제 중계는 문두 필러가 30%대 | `자,` `아,` `네,` `그런데` `여기서` 를 25~35% 확률로 prepend. **연속 금지 + 같은 필러 3연속 금지** |
| 7 | **선수 지칭 불변** | 항상 `name.ko` 풀네임 | 한국어는 이름이 짧아 풀네임 반복이 영어보다 덜 어색하지만, 그래도 100%는 기계적 | 지칭 링: 풀네임 → `이 선수` → `{번호}번` → `{포지션/역할}` → 풀네임. 단, 골 순간은 항상 풀네임(+연호) |
| 8 | **레지스터 무단계** | 0-0 20분 슛과 89분 동점 찬스가 같은 풀 | 긴장이 축적되지 않음 | `intensity 0~3` 축. 입력: 골 종류, 분, xG/찬스질, 점수차, 흐름. 템플릿마다 `intensity` 태그 |
| 9 | **화자 1명** | 캐스터만 | 방송이 아니라 알림 로그로 들림 | 해설 라인 추가, 이벤트의 30~40%에만 |
| 10 | **구두점 균일** | `.` 아니면 `!` | 구두점이 곧 TTS 운율 신호인데 안 씀 (§5) | `…` `?` `!` `,` 를 레지스터 신호로 사용 |
| 11 | **스코어 미인지** | `goal` 템플릿에 선제/동점/역전 구분 없음 | 축구를 모르는 화자로 들림 | §3.1 판정 로직 |
| 12 | **반복 장치 없음** | 없음 | 골의 카타르시스가 안 산다 | `{선수}! {선수}!` — 경기당 3회 상한 |

### 4.2 제안 시그니처

```ts
type CommentaryCtx = {
  minute: number
  half: 1 | 2 | 'et1' | 'et2' | 'pens'
  addedTime: number
  score: { home: number; away: number }
  wasBehind: Record<TeamId, boolean>     // 역전골 판정용
  recentEvents: MatchEvent[]             // 최근 ~15분 (streak 판정)
  playerGoals: Record<PlayerId, number>  // 멀티골/해트트릭
  flow: 'dominant' | 'lull' | 'endToEnd' | 'lowBlock' | 'even'
  tacticChange?: { kind: TacticKind; verdict: 'good' | 'bad' | 'pending' }
  stage: 'group' | 'ko16' | 'qf' | 'sf' | 'final'
  userTeamId: TeamId
  recentLineIds: string[]                // 반복 억제 링버퍼
  seed: number                           // 경기 시드 (결정론 유지)
}

type Line = {
  id: string          // 반복 억제 키
  speaker: 'caster' | 'analyst'
  text: string        // 화면 표시 — 고오오올, !!!, … 허용
  speech: string      // TTS 전용 — §5 규칙 통과 문자열
  intensity: 0 | 1 | 2 | 3
  lengthClass: 'burst' | 'short' | 'mid' | 'long'
}

export function commentate(e: MatchEvent, ctx: CommentaryCtx): Line[]
```

`text`/`speech` 분리가 §5의 전제다. 결정론(같은 이벤트 = 같은 문장)은 `ctx.seed` 로 유지되니 기존 테스트 계약은 지킬 수 있다.

## 5. TTS 친화성 (Web Speech API + ko-KR)

프로젝트는 `speechSynthesis` 를 쓴다(`src/audio/commentary-tts.ts`). 이게 제약을 결정한다.

### 5.1 SSML — 쓰면 안 됨 (확정)

브라우저 대부분이 `SpeechSynthesisUtterance` 의 SSML 마크업(`<break>`, `<prosody>`, `<emphasis>`)을 **무시**하고, **macOS/Safari는 태그를 그대로 읽어버린다** — `"break time 500 밀리세컨드"` 가 소리로 나온다. 어떤 주요 브라우저도 신뢰성 있게 지원하지 않는다. 이 프로젝트에서 SSML은 금지. — [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/text), [browser-compat-data #15663](https://github.com/mdn/browser-compat-data/issues/15663)

### 5.2 장치별 생존 여부

| 장치 | TTS | 설명 | 처방 |
|---|---|---|---|
| `,` (쉼표) | ✅ | 엔진 불문 짧은 pause. **가장 이식성 높은 유일한 pause 수단** | 호흡 지점마다 쉼표 |
| `.` | ✅ | 문장 끝 pause + 하강 억양 | |
| `?` | ✅ | ko-KR 음성이 **실제로 상승 억양** 적용 | `이거 들어가나요?` — 긴장 연출에 적극 활용 |
| `!` | ⚠️ | ko-KR은 대부분 `.` 과 동일 처리. **흥분이 소리로 안 나옴** | `!` 에 의존 금지. 흥분은 `pitch` 로 |
| `…` `...` | ⚠️ | 엔진마다 다름. Apple 음성은 무시하거나 `.` 처리 | 화면용으로만. 음성엔 `,` 또는 유터런스 분할 |
| `!!!` | ❌ | 무시되거나 이상한 pause | speech 문자열에서 `!` 1개로 정규화 |
| **`고오오올`** | ❌ | ko-KR G2P가 `고.오.오.올` **4음절 각각 정상 길이**로 읽음 → 늘어지는 함성이 아니라 **말더듬**으로 들림 | `text: "고오오올!!!"` / `speech: "골! 골입니다!"` — **dual output이 필요한 결정적 이유** |
| `아아아` | ❌ | 동일 | `speech: "아,"` |
| 이모지 | ❌ | 이름으로 읽히거나(`⚽`→"축구공") 무음 | speech에서 제거 |
| 줄바꿈 | ⚠️ | Chrome은 break, Safari는 무시 | 의존 금지 |

### 5.3 숫자 — 한국어 TTS의 최대 함정

분은 **한자어** 수사, 번째/개는 **고유어** 수사. 엔진이 이걸 자주 틀린다. 안전책은 **템플릿 단계에서 한글로 확정해 넣는 것**.

| 쓰면 안 됨 | 읽히는 결과 | 대신 쓸 것 |
|---|---|---|
| `12'` | `십이` + 어포스트로피 이상 처리 / 무음 | `전반 12분` → "전반 십이분" ✅ (분=한자어, 정상) |
| `1:0` | `대` / 무시 / `콜론` — 엔진마다 다름 | **`일 대 영`** (한글 확정) |
| `1-0` | `일 빼기 영` / `일 마이너스 영` | 절대 금지 |
| `90+3` | `구십 더하기 삼` | `후반 추가시간 3분` |
| `3번째` | `삼번째` (오독. 번째는 고유어) | **`세 번째`** — 한/두/세/네/다섯 하드코딩 |
| `2골` | `이골` (허용되나 어색) | `두 골` |
| `7번` (등번호) | `칠번` ✅ | 그대로 OK (등번호=한자어) |
| `62%` | `육십이 퍼센트` ✅ | OK |

**스코어 한글화 테이블** (0~5면 충분):
```ts
const SCORE_KO = ['영','일','이','삼','사','오','육','칠','팔','구']
const scoreKo = (a:number,b:number) => `${SCORE_KO[a]} 대 ${SCORE_KO[b]}`
// 1:0 → "일 대 영"   2:2 → "이 대 이"
```
`0` 은 엔진에 따라 `제로`로 읽을 수 있으므로 반드시 `영`으로 확정.

**고유어 서수 테이블**:
```ts
const ORD_KO = ['','첫','두','세','네','다섯','여섯','일곱','여덟','아홉','열']
// `${ORD_KO[n]} 번째`   (n=1은 "첫 번째")
```

### 5.4 영문·약어

**ko-KR 유터런스에 라틴 문자를 절대 넣지 말 것.** Chrome의 Google ko-KR 음성은 영어식으로 튀거나 철자를 읽고, Apple Yuna는 한글 자모 이름(`에이`, `비`)으로 읽거나 건너뛴다.

```
KOR / BRA          → 대한민국 / 브라질        (name.ko 필수)
GK                 → 골키퍼
PK                 → 페널티킥
VAR                → 비디오 판독   ← "브이에이아르"보다 안전하고 실제 중계 표현
vs                 → 대
FW/MF/DF           → 공격수 / 미드필더 / 수비수
```
액션 아이템: **모든 팀·선수에 `name.ko` 가 채워져 있는지 검증하는 테스트 1개** 추가. 하나라도 비면 TTS가 라틴 문자를 만난다.

### 5.5 조사(josa) 자동 선택 — 텍스트·음성 동시 버그

`` `${player}가` `` 같은 템플릿은 `손흥민가` 를 만든다. 화면에서도 틀리고, TTS는 그 틀린 조사를 **소리로** 읽는다. 선수 이름이 데이터 주도이므로 반드시 헬퍼가 필요하다.

```ts
function hasBatchim(s: string): boolean {
  const c = s.charCodeAt(s.length - 1)
  if (c < 0xAC00 || c > 0xD7A3) return false   // 한글 음절이 아니면 받침 없음 취급
  return (c - 0xAC00) % 28 !== 0
}
const 이가 = (s:string) => s + (hasBatchim(s) ? '이' : '가')
const 은는 = (s:string) => s + (hasBatchim(s) ? '은' : '는')
const 을를 = (s:string) => s + (hasBatchim(s) ? '을' : '를')
const 과와 = (s:string) => s + (hasBatchim(s) ? '과' : '와')
// 으로/로 는 ㄹ받침 예외: jongseong index 8 === 'ㄹ'
const 으로로 = (s:string) => {
  const c = s.charCodeAt(s.length - 1)
  const j = (c >= 0xAC00 && c <= 0xD7A3) ? (c - 0xAC00) % 28 : 0
  return s + (j === 0 || j === 8 ? '로' : '으로')
}
```

### 5.6 극적 pause 만들기 — 유터런스 체이닝

Web Speech에는 유터런스 **내부** pause 제어가 없다. 하지만 유터런스를 **쪼개서 연속 발화**하면 그 사이 간격이 엔진 무관하게 생긴다. 이게 SSML `<break>` 의 유일한 실용 대체재이고, 덤으로 **청크별 rate/pitch 분리**가 가능해진다.

```
"슛!"          → rate 1.25, pitch 1.25   (짧고 날카롭게)
   ↓ onend (자연 간격 ~120ms)
"…막았습니다!"  → rate 0.95, pitch 1.30   (느리고 높게 = 감탄)
```

현재 `speak()` 는 important일 때 `cancel()` 후 단일 발화다. **작은 청크 큐**로 확장 권장 — `speakSequence(chunks: {speech, rate, pitch}[])`, 각 `onend` 에서 다음 발화, `stopAll()` 은 큐도 비움.

### 5.7 rate/pitch 재조정 권고

현재 `important → rate 1.15 / pitch 1.15`. 그런데 **한국어 중계의 흥분은 "빠름"이 아니라 "높고 크고 길게"** 다. rate를 올리면 골 순간의 가장 중요한 정보(선수 이름)가 뭉개진다.

```
권고:
  일반   rate 1.05  pitch 1.00
  중요   rate 1.00  pitch 1.30  volume 1.0     ← rate를 올리지 말 것
  피크   rate 0.95  pitch 1.35                 ← 골 순간은 오히려 느리게
  해설   rate 1.00  pitch 0.95                 ← 화자 구분이 소리로 드러남
```
`pitch` 를 캐스터/해설로 갈라두면 보이스가 하나여도 **두 사람처럼 들린다.** 투입 대비 효과가 가장 큰 한 줄이다.

### 5.8 기타 실무 주의

- Chrome은 ~15초 넘는 유터런스를 잘라먹는 알려진 버그가 있다. 중계 라인은 원래 짧으니 문제없지만, 해설 long 클래스는 30음절 이내로 상한.
- `pickSpokenEvent()` 우선순위에 `goal` 이 최상위인 건 맞다. 다만 §3 도입 후엔 **선제골/역전골/극장골이 일반 추가골보다 우선**해야 하므로 우선순위를 이벤트 타입이 아니라 `Line.intensity` 로 바꾸는 게 맞다.

## 6. 즉시 착수 우선순위

효과/비용 비율 순:

1. **`text`/`speech` 분리** — §5 전체의 전제. 이거 없이는 `고오오올` 도 스코어 한글화도 불가.
2. **분 접두 제거** → UI 타임스탬프로 이동. 한 줄 변경으로 로봇 느낌의 최대 지분이 사라진다.
3. **변형 선택자 교체** — 현재 것은 지각 가능한 주기를 만든다. 실제 해시 + 최근 사용 억제.
4. **`ctx` 도입 + 골 종류 판정(§3.1)** — 선제/동점/역전/쐐기/추격. 축구를 아는 화자로 바뀐다.
5. **조사 헬퍼(§5.5)** — 명백한 버그.
6. **streak 4단어(`또`/`이번에도`/`벌써`/`연속`)(§3.3)** — 상태 하나로 "기억하는 중계".
7. **해설위원 2번째 화자 + pitch 분리(§5.7)** — 방송처럼 들리기 시작.
8. **소강 상태 라인(§3.4)** — 침묵 구간 제거.
9. **전술 반영 해설(§3.5)** — 매니저 게임 차별점.

세이프가드 §7.1 관련: 위 모든 문장은 사실 서술형 또는 전술 의견 범위이며 실존 인물 비하가 없다. 리서치 과정에서 나온 송재익 스타일 조롱 비유(`약먹은 병아리`, `막대기 없는 대걸레` 등 — 실제 중계 어록)는 **의도적으로 전부 배제**했다. §3.7의 편파 화법도 "자기 팀 응원"만 허용하고 "상대 폄하"는 제외했다. 다만 `우리`, `대~한민국` 같은 1인칭 편파 표현은 세이프가드 필터의 금지어 목록과 충돌하지 않는지 한 번 확인이 필요하다.
